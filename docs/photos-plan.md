# 사진 관리 설계 (2026-11 결정)

홈페이지 주인과 Claude가 정한 사진(상장·장학증서·임명장·수료증·활동 사진) 관리 방식이다.
**상태: 설계만 확정, 아직 만들지 않음.** 만들기 전까지의 임시 처리는 맨 아래에 있다.

## 목표
- 주인은 스캔하고 자르기까지만 한다. 휴대폰에서 Claude에게 사진을 보내면 나머지는 Claude가 한다.
- 비용 0원, 새 계정 없음, Claude 토큰은 적게.
- 홈페이지 리포지토리(공개)에는 사진이 쌓이지 않는다. 지운 사진이 공개 기록에 남지 않게 하려는 것이다.

## 구조
```
jyongrhee/photos (Private)         사진 창고. 처리된 사진만 넣는다
  honors/<id>.jpg  scholarships/<id>.jpg  activities/<id>.jpg  certificates/<id>.jpg
  inbox/                            주인이 여러 장을 한꺼번에 올리는 곳 (선택)
        │ 신뢰된 단계만 읽기 전용 토큰(PHOTOS_TOKEN)으로 가져옴
        ▼
jyongrhee.github.io의 Actions       photos 단계(main 코드만 실행) → Actions 캐시에 저장
        ▼                           site·PR 미리보기 빌드는 캐시에서 사진만 받음 (토큰 없음)
홈페이지                             웹용 사진만 공개
```
- 사진은 항목의 **고유 ID**로 연결한다. `honors.json`/`activities.json`의 각 항목에 `"id"`를 붙이고, 파일 이름을 `<id>.jpg`로 한다. 여러 장이면 `<id>-2.jpg`, `<id>-3.jpg`. 지금의 날짜+단어 자동 연결은 이 방식으로 바꾼다.
- 단계 사이에서 사진은 아티팩트가 아니라 **Actions 캐시**로 넘긴다. 공개 리포지토리의 아티팩트는 GitHub에 로그인한 누구나 내려받을 수 있기 때문이다.
- photos가 없거나 비어 있으면 아무것도 하지 않는다. 기존 `media/hero.jpg`와 로고는 홈페이지 리포지토리에 그대로 둔다.

## 상장 등록 흐름 (B 방식)
1. 주인: 어도비 스캔으로 찍고 자른 JPG를 Claude에게 공유한다.
2. Claude: 촬영 정보와 GPS를 지우고, 상장 글씨를 읽어 확인표를 보여 준다. 확인표에는 종류, 등급, 상 이름(한/영), 기관, 날짜, ID가 들어간다. 확실하지 않은 정보는 추측하지 않고 묻는다.
3. 주인: "ㅇㅋ"라고 하거나 고칠 점을 말한다.
4. Claude: photos에 올리고, 홈페이지 PR을 만든다. 검사가 통과하면 **바로 합친다.** 반영되면 링크로 알린다.
   - 주인이 "수정해"라고 하면, 그 건은 미리보기를 보여 주고 "합칠까요?"로 확인받은 뒤 합친다.
5. 디자인·기능 변경은 이 흐름이 아니다. 지금처럼 미리보기를 보여 주고 확인받는다.

## 삭제와 기록
| 상황 | 처리 |
|---|---|
| 일반 삭제 | photos와 홈페이지에서 삭제한다. photos의 비공개 기록에는 남아 복구할 수 있다 |
| 실수로 삭제 | photos 기록에서 되살린다 |
| 민감한 사진 | photos 기록을 정리하고, 예전 공개 주소가 404가 되는지 확인한다 |
| 용량 증가 | 주인이 요청할 때만 photos 기록을 정리한다 |
| 중요한 원본 | 주인이 PC나 드라이브에 따로 백업한다. Git 기록은 백업이 아니다 |

- 배포할 때마다 공개 사진 목록을 비교해서, 빠진 사진의 예전 주소가 404가 되는지 확인한다(최대 10~15분 재시도). 남아 있으면 경고한다.
- "기록 정리"는 접근 가능한 기록에서 빼는 것이지 완전 삭제가 아니다. 이미 내려받은 사람의 사본은 지울 수 없다.

## 보안
- 비공개 리포지토리의 안전은 계정 보안에 달려 있다. 주인은 GitHub 2단계 인증을 켜 둔다.
- `PHOTOS_TOKEN`: photos 하나만, Contents 읽기 전용, 1년 만료(만료 전 갱신). 주인이 Secrets에 직접 넣는다. 채팅에는 붙여 넣지 않는다.
- 주민번호처럼 아주 민감한 정보가 보이는 원본은 비공개라도 올리지 않는다. 보이는 개인정보는 주인이 미리 가린다.
- PDF는 저장하지 않는다. 페이지를 JPG로 바꿔 넣는다. 숨은 정보와 가린 상자 밑의 글자가 사라진다.

## 토큰 아끼기
- 상장 한두 장은 채팅으로 공유한다(B 방식).
- 여러 장은 휴대폰 브라우저로 photos `inbox/`에 올리고, "inbox 정리해줘"와 함께 파일마다 한 줄 설명을 보낸다. 이렇게 하면 Claude가 사진을 열어 보지 않는다.
- 작업마다 새 대화를 쓰거나, 상장 등록 전용 대화를 하나 계속 쓴다.
- 모델: 상장·사진 등록은 Sonnet(최신), 시스템 구축과 디자인 변경은 Opus.

## 만들 순서
1. 주인: `jyongrhee/photos`를 Private으로 만든다(README 포함).
2. 주인: `PHOTOS_TOKEN`을 만들어 `jyongrhee.github.io` Secrets에 넣는다. 2단계 인증도 확인한다.
3. 주인: 세션에 photos 쓰기 권한을 허락한다.
4. Claude: 쓰기·지우기를 시험한다.
5. Claude: 고유 ID 도입, 빌드·워크플로 수정, 문서 작업을 PR로 올린다. 이 작업은 Opus로 한다.
6. 함께: 시험 사진 1장으로 추가 → 교체 → 삭제 → 404 확인까지 해 본다.

## 만들기 전까지
photos 시스템이 생기기 전에 사진 등록을 요청받으면, Claude는 이 상태를 알리고 두 가지 중에서 고르게 한다.
- photos 시스템을 먼저 만든다.
- 이번 사진만 홈페이지 리포지토리 `media/`에 넣는다. 처리한 사진만 넣지만, 공개 기록에 영원히 남는다.
